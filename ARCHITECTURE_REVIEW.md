## Summary
The codebase follows a clear domain/components/pages/lib split with well-documented 'pre-built' UI primitives (ScreenScaffold, Card, SummaryHero) and consistent SDK-guarding conventions (try/catch around Toss WebView APIs). However, it shows real duplication (haptic-fire wrappers, date formatting, storage keys reimplemented per-file), a stale scaffold artifact (lib/contract.ts) that duplicates lib/types.ts, and several components/pages that appear unreferenced by any route, suggesting incomplete wiring or leftover scaffolding. No circular imports were observed.

## Issues
### Warnings
- [duplication] The 'fire a haptic feedback safely' pattern (Promise.resolve(generateHapticFeedback(...)).catch(()=>{}) wrapped in try/catch because the SDK throws outside WebView) is independently reimplemented in at least 5 places with slightly different names and signatures instead of one shared utility. — Files: src/components/BottomCTA.tsx, src/components/ReportGate.tsx, src/components/FloatingTabBar.tsx, src/pages/Quiz.tsx, src/pages/History.tsx / Fix: Extract a single `fireHaptic(type)` helper into e.g. src/lib/haptics.ts and import it everywhere instead of redefining local fireHaptic/safeHaptic functions.
- [duplication] `formatDate(ts)` (YYYY.MM.DD formatting) is defined identically, byte-for-byte, in two separate list components. — Files: src/components/CompatHistoryList.tsx, src/components/ResultHistoryList.tsx / Fix: Move formatDate into src/lib/utils.ts (alongside formatNumber/formatCurrency) and import it from both list components.
- [consistency] localStorage keys ('mp.quiz.draft', 'mp.result.latest', 'mp.result.history', 'mp.compat.history') are hardcoded as separate string constants in multiple files instead of a single source of truth, risking silent drift/typos between reader and writer. — Files: src/pages/Calculating.tsx, src/pages/History.tsx, src/state/useQuizDraft.ts / Fix: Centralize all storage keys in one module (e.g. src/lib/storageKeys.ts) and import from there in every page/hook that reads or writes them.
- [consistency] src/lib/storage.ts already provides a safe getItem/setItem/removeItem abstraction (try/catch + JSON parse), but History.tsx bypasses it with its own hand-rolled `loadArray` that talks to `localStorage` directly and duplicates the corruption-recovery logic. — Files: src/pages/History.tsx, src/lib/storage.ts / Fix: Extend lib/storage.ts with a getArray<T>(key) helper (array-shape validation + cleanup) and have History.tsx use it instead of a local loadArray.
- [dead_code] src/lib/contract.ts redeclares an entire parallel type system (Question, Persona, QuizDraft, Result, RouteState, plus ~20 *Fn types) that overlaps with and diverges from the real types in src/lib/types.ts (e.g. `Result` vs `QuizResult`, `Question.options: string[]` vs the real `{key,label,value}[]` shape). It reads as an autogenerated scaffold artifact that nothing in the reviewed codebase imports. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Delete contract.ts once real implementation exists (or move it to a docs/ folder clearly marked non-runtime), and keep lib/types.ts as the single source of truth to prevent future drift.
- [dead_code] Several exported components are not imported by any page/route in the reviewed set: Amount, CountUp, MiniBar, TossPurchase, TossRewardAd, ReportGate, ReportContent. ROUTES (routes.tsx) only wires Home/Quiz/Calculating/History plus a Compat placeholder — no /report or /share screen appears to consume ReportGate/ReportContent, and TossRewardAd duplicates ReportGate's ad-gating role without being used anywhere. — Files: src/components/Amount.tsx, src/components/CountUp.tsx, src/components/MiniBar.tsx, src/components/TossPurchase.tsx, src/components/TossRewardAd.tsx, src/components/ReportGate.tsx, src/components/ReportContent.tsx / Fix: Either wire these into the routes that need them (Report/Share pages) or remove them until those screens are built, to avoid maintaining unused, divergent implementations of the same ad-gating concept.
- [consistency] Two separate components implement full-screen reward-ad gating with divergent policies: ReportGate persists unlock only on explicit watch-completion and never auto-unlocks on failure, while TossRewardAd auto-unlocks on load failure/timeout/non-WebView.
