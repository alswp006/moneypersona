## Summary
The codebase is a small React/TypeScript App-in-Toss mini-app (12-question persona quiz) with generally clean, well-commented components and a sound page/component/lib separation. The biggest structural risk is a stale `lib/contract.ts` spec file whose types actively contradict the real `lib/types.ts` schema, plus several components and utilities that are exported but never wired into any page, and repeated ad-hoc logic (haptics, localStorage envelope unwrapping, axis-letter mapping) that should be centralized. Import-path and export-style conventions also drift between files, suggesting multiple contributors/generations without a shared lint/style pass.

## Issues
### Critical
- [consistency] src/lib/contract.ts defines a parallel, incompatible type schema (Question, Persona, QuizResult, AxisScores, etc.) that conflicts with the actual runtime types in src/lib/types.ts (e.g. contract's Question has {id:string; options:string[]}, but the real Question in types.ts has {id:number; choices:[Choice,Choice]}). None of contract.ts's types are imported anywhere in the shown codebase. If future 'packet' work is generated against this file it will produce code incompatible with the real implementation. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Delete contract.ts if it's an obsolete planning artifact, or regenerate it from the actual lib/types.ts so the two never diverge. Add a CI check or comment linking the two if both must be kept.

### Warnings

- [duplication] The haptic-feedback fire-and-forget pattern (`Promise.resolve(generateHapticFeedback(...)).catch(()=>{})` wrapped in try/catch for WebView-outside safety) is independently re-implemented in three places with slightly different signatures. — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/pages/Quiz.tsx / Fix: Extract a single `fireHaptic(type)` utility (e.g. src/lib/haptics.ts) and import it everywhere instead of re-implementing the try/catch guard.

### Suggestions
- [duplication] The AXIS_LETTERS ([highLetter, lowLetter] per axis) mapping is duplicated verbatim between scoring.ts and shareCode.ts; shareCode.ts's comment even acknowledges the duplication ('scoring.ts의 AXIS_LETTERS와 동일한 매핑'). — Files: src/lib/scoring.ts, src/lib/shareCode.ts / Fix: Export AXIS_LETTERS once from scoring.ts (or a shared lib/axis.ts) and import it in shareCode.ts to guarantee the mappings can't drift.
- [duplication] Amount.tsx and CountUp.tsx both re-implement the identical wrapper (`<span>` with nowrap + tabular-nums + maxWidth:100% + Paragraph.Text) around a formatted number, differing only in the value animation. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract a shared `NumberDisplay` presentational wrapper that both Amount and CountUp compose, so the nowrap/tabular-nums styling lives in one place.
- [naming] DisclaimerNotice.tsx uses a default export while every other component in src/components uses named exports, breaking the otherwise-consistent import convention. — Files: src/components/DisclaimerNotice.tsx, src/components/Card.tsx, src/components/SummaryHero.tsx / Fix: Convert DisclaimerNotice to a named export (`export function DisclaimerNotice`) to match the rest of the component library.
- [consistency] Quote style is inconsistent: most files under src/components use double quotes while src/App.tsx, src/main.tsx, and most src/pages files use single quotes, suggesting no shared Prettier config is enforced. — Files: src/components/Card.tsx, src/App.tsx, src/pages/Home.tsx / Fix: Add/enforce a single Prettier config (singleQuote: true or false) and run it repo-wide in CI.
- [structure] src/components is a flat folder mixing unrelated concerns — generic UI primitives (Card, Amount, MiniBar), ad SDK wrappers (AdSlot, TossRewardAd), and IAP payment wrapper (TossPurchase) — with no subgrouping, making it harder to see which components are page-agnostic UI vs. third-party SDK integrations. — Files: src/components/AdSlot.tsx, src/components/TossPurchase.tsx, src/components/TossRewardAd.tsx, src/components/Card.tsx / Fix: Split into subfolders, e.g. components/ui/ (Card, Amount, CountUp, MiniBar, Sparkline, StateView) and components/toss/ (AdSlot, TossPurchase, TossRewardAd) to separate design-system primitives from SDK integrations.
- [structure] Report.tsx, Share.tsx, Compat.tsx, and History.tsx are near-duplicate placeholder scaffolds (same ScreenScaffold + Card + explanatory text + single CTA shape) with almost no differentiating logic yet, which is fine as scaffolding but risks copy-paste drift once each is fleshed out by different feature packets. — Files: src/pages/Report.tsx, src/pages/Share.tsx, src/pages/Compat.tsx, src/pages/History.tsx / Fix: Consider a shared `PlaceholderScreen` component (top title + card message + CTA) for the not-yet-implemented routes, replaced page-by-page as each feature packet lands.
